# SARINE Website: Netlify to Firebase Hosting Migration Guide

This guide details the completed migration of the **SARINE** jewellery e-commerce frontend from Netlify to **Firebase Hosting**, preserving all existing functionality, database queries, authentication flows, and payment integrations.

---

## 1. Project Audit Summary

- **Frontend Framework**: React 19 SPA with TypeScript and Vite 8.
- **Styling**: Tailwind CSS v4 (`@import "tailwindcss";` in global CSS).
- **Client Routing**: React Router v7 with deep routes (`/`, `/shop`, `/product/:slug`, `/order/:orderNumber`, `/track-order`, `/account`, `/admin/orders`).
- **Build Output**: `dist/` generated by `npm run build` (`vite build`).
- **Database & Auth**: Client-side Firebase SDK v13 connected directly to Cloud Firestore & Firebase Auth (`sarine-cbcce`).
- **Serverless Backend**: Netlify TypeScript functions (`netlify/functions/`) using `firebase-admin` and `razorpay` for secure transactions.

---

## 2. Firebase Hosting Configuration Files

### `firebase.json`
- **Public Directory**: `dist`
- **SPA Rewrites**: All incoming deep routes (`/**`) route to `/index.html` with status 200, ensuring page refreshes and direct links never return 404s.
- **Cache-Control Headers**:
  - `/assets/**`: `public, max-age=31536000, immutable` (hashed CSS/JS chunks cached for 1 year).
  - `/index.html` & `**/*.html`: `no-cache, no-store, must-revalidate` (guarantees customers always get fresh releases).
- **Security Headers**:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: SAMEORIGIN`
  - `X-XSS-Protection: 1; mode=block`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`

### `.firebaserc`
Configured with default project:
```json
{
  "projects": {
    "default": "sarine-cbcce"
  }
}
```

## 3. Plan & Cost Analysis: Spark (Free) vs. Blaze (Pay-as-you-go)

| Capability | Spark Plan (100% Free) | Blaze Plan (Pay-as-you-go) |
|---|---|---|
| **Firebase Hosting** | **Free** (10 GB storage, 360 MB/day transfer, custom domains + SSL) | Free allowance, then $0.026/GB |
| **Firebase Auth** | **Free** (Unlimited email/password) | Free (Email/password) |
| **Firestore Database** | **Free** (50,000 reads, 20,000 writes, 1 GB storage/day) | Free tier included, pay per use beyond |
| **Cloud Functions** | ❌ **Blocked**: Outbound internet requests (e.g. to `api.razorpay.com`) are prohibited | ✅ Allowed (Includes 2M free invocations/month; requires credit card) |

### Recommended Architecture: Hybrid (Zero Cost)
To keep the website **100% free** without adding a credit card:
1. **Frontend Hosting**: Firebase Hosting (Spark Plan) — fast global CDN, free SSL, custom domain.
2. **Serverless API**: Netlify Free Tier (125,000 requests/month, 100 runtime hours free) — allows outbound networking to Razorpay without credit card requirements.
3. **Connection**: Frontend calls the backend using the dynamic endpoint resolver (`src/config/api.ts`). Simply set `VITE_API_BASE_URL=https://<your-netlify-site>.netlify.app/.netlify/functions` in your environment.

*(If you ever upgrade your Firebase project to Blaze, you can deploy Cloud Functions directly to Firebase and set `VITE_API_BASE_URL=/api`)*.

## 4. Cross-Origin (CORS) Hardening & Origin Allowlist

Because the frontend is hosted on Firebase Hosting (`sarine-cbcce.web.app` or your custom domain) and communicates with backend functions, wildcard `*` CORS has been completely removed and replaced with a strict origin allowlist in `netlify/functions/utils/security.ts`:
- **Default Allowed Origins**:
  - `https://sarine-cbcce.web.app` (Primary Firebase Hosting production domain)
  - `https://sarine-cbcce.firebaseapp.com` (Secondary Firebase Hosting production domain)
  - `http://localhost:3000`, `http://localhost:5173`, `http://localhost:8888` (Local dev servers)
  - `http://127.0.0.1:3000`, `http://127.0.0.1:5173`, `http://127.0.0.1:8888`
- **Dynamic Origin Extension**:
  - Any additional custom domains can be added via the server environment variable `ALLOWED_ORIGINS` (comma-separated, e.g. `https://sarine.in,https://www.sarine.in`) or `CUSTOM_DOMAIN` (e.g. `sarine.in`).
- **Preflight & Header Spec**:
  - `Access-Control-Allow-Origin: <matching-origin>` (or default `https://sarine-cbcce.web.app` if untrusted/missing)
  - `Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With, Accept`
  - `Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS`
  - `Access-Control-Max-Age: 86400`
  - `Vary: Origin`
- All Netlify functions handle `OPTIONS` preflight requests returning HTTP 204 with 0-byte payload.
- **Security Rule**: CORS is not treated as authorization. Every stateful endpoint verifies the Firebase ID token or the cryptographically secure 32-byte `publicToken`.

## 5. GitHub Actions Deployment Automation

Two automated workflows are configured in `.github/workflows/`:
1. **`firebase-hosting-merge.yml`**: Triggers on push/merge to `main` or `master`. Runs `npm run lint` (`tsc --noEmit`), `npm run build`, and deploys to the **live** Firebase channel.
2. **`firebase-hosting-pull-request.yml`**: Triggers on pull requests and deploys a temporary preview channel URL with comments on the PR.

### Setting up the GitHub Secret
1. Run in terminal:
   ```bash
   firebase init hosting:github
   ```
   Or create a Google Cloud Service Account with the **Firebase Hosting Admin** role.
2. Add the JSON key as a secret named `FIREBASE_SERVICE_ACCOUNT_SARINE_CBCCE` in your GitHub repository:
   *Settings > Secrets and variables > Actions > New repository secret*.

## 6. Manual Deployment from Local Terminal

To deploy manually at any time:
```bash
# 1. Install Firebase CLI (if not already installed)
npm install -g firebase-tools

# 2. Login to Firebase
firebase login

# 3. Build the frontend
npm run build

# 4. Deploy only hosting
npm run deploy:hosting
# or
firebase deploy --only hosting
```

## 7. Custom Domain & DNS Setup

To connect your custom brand domain (e.g., `sarinejewelry.com`):
1. In the [Firebase Console](https://console.firebase.google.com/project/sarine-cbcce/hosting/sites), click **Add custom domain**.
2. Enter your domain name (e.g. `sarinejewelry.com` and `www.sarinejewelry.com`).
3. Add the two DNS `A` records provided by Firebase to your domain registrar (GoDaddy, Namecheap, Cloudflare, etc.).
4. Firebase automatically provisions and renews free SSL certificates (usually takes 15–60 minutes).
5. In Razorpay Dashboard, if using Webhooks, verify your webhook URL points to your active serverless backend.
